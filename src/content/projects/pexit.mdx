## Problem

Pexit is a professional networking platform for companies, profiles and listings. It needed its core backend systems, including authentication, the social graph, the feed and asset storage, built to production standards.

## What I built

- **Authentication, rebuilt end to end:** split access and refresh JWTs bound to Redis-backed sessions, AES-256-GCM token encryption, Redis-backed OTP attempt limiting and a global Redis rate limiter.
- **The Circle social-graph module** on Neo4j with the Cypher query builder, powering connections, mutual-connection lookups and recommendation candidates.
- **Posts, comments and the feed** on Fastify and PostgreSQL, with visibility rules, blocking-aware feeds, media attachments and HTML sanitisation, plus the React feed, composer, comments and repost UI.
- **A multi-bucket asset service** on Supabase Storage, with Companies, Profiles, Listings and Posts migrated off the earlier single-bucket storage.
- **The Listings module's** per-type service and data-access layers, with location, category and pagination filters, new REST endpoints and React pages.

## Key decisions

**Sessions bound to Redis.** Refresh tokens are tied to server-side sessions, so sessions can be revoked on the server.

**A graph database for the social graph.** Connections and mutual-connection lookups run on Neo4j.

**Tests against a real PostgreSQL.** Every module has Vitest unit tests and integration tests against a real Postgres database, plus Playwright end-to-end tests, enforced by pre-commit and pre-push hooks in the Nx and pnpm monorepo.

## Results

- Companies, Profiles, Listings and Posts run on the multi-bucket asset service.
- Every backend module is documented in OpenAPI and covered by automated tests.
