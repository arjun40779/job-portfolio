## Problem

The owner ran several paying-guest houses in Kokrajhar and handled every enquiry by phone and WhatsApp. Availability lived in a notebook, so the same room was occasionally promised to two people, and prospective guests had no way to see rooms, photos or prices before calling.

He wanted a site that showed each property properly, let guests request a room without a phone call, and that he could keep up to date himself.

## What I built

- **Listings from a CMS.** Properties, rooms, photos, amenities and prices are modelled in Sanity, so the owner edits them in Sanity Studio without touching code.
- **Accounts and roles.** Supabase Auth with two roles: guests, who can request rooms and see their own requests, and the owner, who sees and manages everything.
- **Availability and booking requests.** Each room has bookings in Supabase Postgres. The listing page shows which dates are free, and a request form creates a pending booking.
- **Owner dashboard.** A protected page where the owner approves or declines requests. Approving a request blocks those dates for everyone else.
- **Deployment.** Next.js on Vercel, with listing pages statically generated and refreshed by a Sanity webhook when content changes.

## Key decisions

**Sanity for content, Supabase for transactions.** Rooms and photos change rarely and need a friendly editor; bookings change constantly and need a database with constraints. Splitting them let the owner edit content in a polished UI while booking data stayed relational and consistent. The alternative, keeping everything in Supabase, would have meant building an admin UI for photos and text.

**Row-level security instead of a custom API.** Postgres row-level security policies enforce that guests can only read and create their own bookings, and only the owner role can approve them. That kept the backend small, with the rules living next to the data.

**Static pages with on-demand revalidation.** Listing pages are generated at build time and revalidated through a Sanity webhook, so they load fast on slow mobile connections. Availability is fetched separately, so it is never stale.

## Results

- The site is live at pginkokrajhar.com, and the owner updates rooms, photos and prices himself.
- Booking requests now arrive through the site with the dates and contact details already filled in, instead of as phone calls.
- Approving a request blocks those dates automatically, which removed the double-booking problem.
